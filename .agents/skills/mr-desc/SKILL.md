# MR 작업 내용 자동 작성

현재 브랜치의 변경 사항을 분석해 팀 MR 템플릿에 맞는 설명을 작성한다.

## 절차

1. **변경 분석**
   - `git fetch origin` 후 `git log --oneline origin/dev..HEAD` 로 이 브랜치의 커밋 확인
   - `git diff origin/dev...HEAD --stat` 으로 변경 파일 목록 확인
   - 주요 변경 파일을 읽고 핵심 구현 내용 파악 (머지 커밋은 제외)

2. **작성 형식** — `.gitlab/merge_request_templates/Default.md` 템플릿 구조를 따른다:
   - `## 📌 작업 내용`: 두괄식 한 문단 요약 (무엇을 왜 구현했는지)
   - `### 세부 구현 내용`: 기능 구분별 표. 스냅샷 셀은 `<img src="" width="250">` 빈 값으로 두고, 어떤 화면을 캡처하면 되는지 기능 구분 열에 명시
   - `## 🔍 주요 코드 설명`: 리뷰어가 봐야 할 핵심 코드 2~4개. 각각 제목 + 설명 + `<details><summary>파일 경로</summary>` 안에 코드 블록
   - 설계 결정(왜 이렇게 했는지)과 버그 수정이 있으면 반드시 포함

3. **출력**
   - 기본: 마크다운 버전 (마크다운 모드 에디터용)
   - 사용자가 리치 텍스트 에디터를 쓰면 문법이 그대로 노출되므로, 요청 시 `#`/표 문법을 뺀 플레인 텍스트 버전도 제공

## 주의

- 커밋 메시지 컨벤션: `S15P11D201-<티켓번호> [FE] feat: <제목>` — MR 제목도 동일 형식 권장
- 목업/TODO로 남긴 부분은 "추후 연동 예정"으로 명시해 리뷰어가 미완성으로 오해하지 않게 한다
- 스냅샷 촬영 가이드(어떤 상태에서 찍을지)를 마지막에 안내한다
