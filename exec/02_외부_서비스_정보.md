## 1. 소셜 인증

로그인은 **카카오 / 구글 두 가지뿐**이다. 두 제공자 모두 흐름이 같다.

```
프론트 → 제공자 동의 화면 → redirect_uri 로 authorization code 수신
     → 백엔드 POST /v1/auth/oauth 로 code 전달
     → 백엔드가 client secret 으로 토큰 교환 + 사용자 정보 조회 → 자체 JWT 발급
```

액세스 토큰은 브라우저에 내려가지 않는다. 코드를 토큰으로 바꾸는 일은 항상 서버가 한다.

### 1.1 카카오 로그인 (Kakao Developers)

- 콘솔: https://developers.kakao.com
- 가입: 카카오 계정으로 로그인 → [내 애플리케이션] → 애플리케이션 추가

| 항목 | 값 |
|---|---|
| REST API 키 (`KAKAO_CLIENT_ID`) | `.env` 참조 (8장) — 콘솔 [앱 키 > REST API 키] |
| Client Secret (`KAKAO_CLIENT_SECRET`) | 사용 안 함 (콘솔에서 비활성, 빈 값) |
| JavaScript 키 (`VITE_KAKAO_JS_KEY`) | `.env` 참조 (8장) — 콘솔 [앱 키 > JavaScript 키] |
| 토큰 발급 URI | `https://kauth.kakao.com/oauth/token` |
| 사용자 정보 URI | `https://kapi.kakao.com/v2/user/me` |
| JS SDK | `https://t1.kakaocdn.net/kakao_js_sdk/2.7.5/kakao.min.js` (SRI 무결성 해시 고정) |

**콘솔에 등록해야 하는 설정**

| 설정 위치 | 등록값 |
|---|---|
| [카카오 로그인 > Redirect URI] | `https://starttoo.duckdns.org/oauth/kakao/callback`<br>`https://localhost:5173/oauth/kakao/callback` |
| [플랫폼 > Web > 사이트 도메인] | `https://starttoo.duckdns.org`, `https://localhost:5173` |
| [카카오 로그인] | 활성화 ON |
| [동의 항목] | 닉네임, 프로필 사진, 이메일 |

**주의**

- Redirect URI는 인가 요청과 토큰 교환에서 **문자 하나까지 같아야 한다**.
  코드에서는 `window.location.origin + /oauth/kakao/callback`으로 만든다
  ([frontend/src/constants/auth.ts](../frontend/src/constants/auth.ts)).
- JavaScript 키는 브라우저에 노출되는 것이 정상이며, 콘솔에 등록된 도메인에서만 동작한다.
- Vite가 빌드 시점에 값을 치환하므로 `VITE_KAKAO_JS_KEY`는 **Compose build arg**로 넘어가야 한다.
  런타임 환경변수로는 주입되지 않는다.
- 로그아웃 후 재로그인 시 `prompt=login`을 붙여 계정 세션이 남아 있어도 재인증을 강제한다.

### 1.2 구글 OAuth 2.0 (Google Cloud Console)

- 콘솔: https://console.cloud.google.com/apis/credentials
- 가입: 구글 계정 → 프로젝트 생성 → [OAuth 동의 화면] 구성 → [사용자 인증 정보 > OAuth 클라이언트 ID(웹 애플리케이션)]

| 항목 | 값 |
|---|---|
| Client ID (`GOOGLE_CLIENT_ID`, `VITE_GOOGLE_CLIENT_ID`) | `.env` 참조 (8장) — `...apps.googleusercontent.com` 형식 |
| Client Secret (`GOOGLE_CLIENT_SECRET`) | `.env` 참조 (8장) — `GOCSPX-` 로 시작 |
| 인가 URL | `https://accounts.google.com/o/oauth2/v2/auth` |
| 토큰 발급 URI | `https://oauth2.googleapis.com/token` |
| 사용자 정보 URI | `https://openidconnect.googleapis.com/v1/userinfo` |
| Scope | `openid email profile` |

**콘솔에 등록해야 하는 설정**

| 설정 위치 | 등록값 |
|---|---|
| 승인된 리디렉션 URI | `https://starttoo.duckdns.org/oauth/google/callback`<br>`https://localhost:5173/oauth/google/callback` |
| 승인된 JavaScript 원본 | `https://starttoo.duckdns.org`, `https://localhost:5173` |

**주의**

- 구글은 카카오와 달리 별도 JS SDK 키가 없고 Client ID를 그대로 인가 URL에 쓴다(공개 값).
- 구글에는 카카오의 `prompt=login`에 해당하는 값이 없어 비밀번호 재입력은 강제할 수 없다.
  재로그인 시 `prompt=select_account`로 계정 선택 화면까지만 보장한다.
- 동의 화면이 "테스트" 상태면 등록한 테스트 사용자만 로그인할 수 있다.

## 2. 도메인 · 인증서

### 2.1 DuckDNS (무료 동적 DNS)

- 사이트: https://www.duckdns.org
- 가입: GitHub/Google 등 소셜 계정으로 로그인하면 토큰과 서브도메인이 발급된다.

| 서브도메인 | 용도 |
|---|---|
| `starttoo.duckdns.org` | 메인 서비스 |
| `starttoo-storage.duckdns.org` | MinIO 오브젝트 공개 엔드포인트 |

- A 레코드는 배포 서버(EC2)의 공인 IP를 가리킨다.
- SSAFY 기본 도메인 `i15d201.p.ssafy.io`도 함께 서비스한다(nginx에 세 개의 가상호스트).
- MinIO를 별도 서브도메인으로 분리한 이유: presigned URL의 Host 서명과 일치시켜야 해서
  nginx가 `Host` 헤더를 그대로 전달해야 하기 때문이다.

### 2.2 Let's Encrypt (TLS 인증서)

- 발급: 호스트의 certbot으로 세 도메인 각각 발급
- 저장 위치: 호스트 `/etc/letsencrypt` → nginx 컨테이너에 **읽기 전용 마운트**
- 인증서 경로

| 도메인 | 경로 |
|---|---|
| `i15d201.p.ssafy.io` | `/etc/letsencrypt/live/i15d201.p.ssafy.io/` |
| `starttoo.duckdns.org` | `/etc/letsencrypt/live/starttoo.duckdns.org/` |
| `starttoo-storage.duckdns.org` | `/etc/letsencrypt/live/starttoo-storage.duckdns.org/` |

- 세 인증서 중 하나라도 없으면 nginx 컨테이너가 기동에 실패한다.
- 갱신은 호스트의 certbot이 담당한다(컨테이너 재생성과 무관하게 유지).

## 3. AI 모델 배포처

모델 가중치는 저장소에 커밋하지 않고 외부에서 받아온다. **가입·API 키가 필요 없는 공개 저장소**다.

### 3.1 Hugging Face Hub

- 사이트: https://huggingface.co
- 인증 불필요 (공개 모델, 익명 다운로드)

| 모델 | repo id | 용도 | 크기 |
|---|---|---|---|
| SigLIP2 | `google/siglip2-so400m-patch16-384` | 타투 subject(도안 소재) 분류 | 약 1.7GB |
| Stable Diffusion v1.5 | `stable-diffusion-v1-5/stable-diffusion-v1-5` | 타투 도안 생성 베이스 모델 | 약 4GB |

- 내려받기: `python -m api_server.download_models` (`huggingface_hub.snapshot_download`)
- SigLIP2는 `ai-siglip` Docker 볼륨에 캐시된다. 볼륨이 없으면 배포(down/up)마다 다시 받는다.
- SD v1.5는 서버에 직접 배치한 경로(`SD15_MODEL_HOST_PATH`)를 읽기 전용 바인드 마운트한다.
  저장소에는 `.gitignore`로 제외돼 있다.
- 컨테이너의 `HOME`이 실제로 존재해야 한다. 없으면 `~/.cache` 생성 실패로 다운로드가
  `Permission denied (os error 13)`로 죽는다 (`ai/Dockerfile`에서 `/home/app`을 미리 만든다).

### 3.2 PyTorch 공식 CPU 휠 인덱스

- URL: `https://download.pytorch.org/whl/cpu`
- 배포 서버에 GPU가 없어 CUDA 빌드(2~3GB) 대신 CPU 전용 휠을 쓴다.
- GPU 머신으로 옮긴다면 `ai/Dockerfile`의 해당 줄을 지우고 `api_server/requirements.txt`에
  `torch`를 되돌린다(`ai/Dockerfile.gpu` 참고).

### 3.3 사내 학습 모델 (외부 서비스 아님)

`inklift_v11_7`(SegFormer 기반 타투 추출)은 팀이 직접 학습한 체크포인트로, 저장소에 포함돼 있다.

## 4. 브라우저에서 직접 호출하는 외부 리소스

AR 시뮬레이션과 InkProof 기능은 **브라우저에서 온디바이스로 추론**한다. 서버를 거치지 않고
아래 공개 CDN에서 모델과 WASM 런타임을 받는다. 가입·키가 필요 없다.

| 서비스 | URL | 용도 |
|---|---|---|
| jsDelivr CDN | `https://cdn.jsdelivr.net/npm/@mediapipe/tasks-vision@0.10.35/wasm`<br>`https://cdn.jsdelivr.net/npm/@mediapipe/tasks-vision@0.10.14`<br>`https://cdn.jsdelivr.net/npm/@huggingface/transformers` | MediaPipe WASM 런타임, transformers.js |
| Google MediaPipe 모델 스토리지 | `https://storage.googleapis.com/mediapipe-models/image_segmenter/selfie_multiclass_256x256/float32/latest/selfie_multiclass_256x256.tflite` | 인물 분할(AR 마스크) |
| Google MediaPipe 모델 스토리지 | `https://storage.googleapis.com/mediapipe-models/pose_landmarker/pose_landmarker_full/float16/1/pose_landmarker_full.task`<br>`.../pose_landmarker_heavy/float16/1/pose_landmarker_heavy.task` | 포즈 랜드마크 |
| Kakao CDN | `https://t1.kakaocdn.net/kakao_js_sdk/2.7.5/kakao.min.js` | 카카오 로그인 SDK |

> 폐쇄망·오프라인 환경에서는 이 리소스들을 받을 수 없어 AR/InkProof와 카카오 로그인이 동작하지 않는다.
> 카메라 기능은 보안 컨텍스트(HTTPS)도 필요하다.

## 5. 코드에는 있으나 현재 사용하지 않는 서비스

| 서비스 | 상태 | 설명 |
|---|---|---|
| **Firebase Cloud Messaging** | **비활성** (`FIREBASE_ENABLED=false`) | 백엔드에 `firebase-admin` 9.10.0과 전송 코드가 있고 `user_devices` 테이블도 있지만, 운영에서 켜지 않았다. 프론트에는 Firebase SDK 자체가 없다. 켜려면 Firebase 콘솔(https://console.firebase.google.com)에서 프로젝트를 만들고 서비스 계정 JSON을 받아 `FIREBASE_SECRETS_DIR`에 두고 `FIREBASE_PROJECT_ID`·`FIREBASE_CREDENTIALS_PATH`를 채운다. 키 파일은 커밋 금지(`.gitignore`의 `*firebase*.json`). |
| **SMS 인증** | **미사용** | 발송 비용 때문에 실제 인증을 하지 않기로 했다. 화면에서 고정 코드 `1111`을 입력받아 번호를 한 번 더 확인시키는 UI 장치일 뿐이며, 서버로 보내지 않는다. `SMS_WEBHOOK_URL`·`SMS_API_KEY`는 빈 값이다. |

## 6. 사용하지 않는 서비스

- **포톤 클라우드(Photon Cloud)** 등 실시간 멀티플레이 서비스 — 사용하지 않음.
  실시간 통신은 백엔드의 STOMP over WebSocket(`/ws`)으로 직접 처리한다.
- **코드 컴파일/실행 서비스**(Judge0 등) — 사용하지 않음. 코드 실행 기능이 없다.
- **결제 PG** — 사용하지 않음.
- **지도 API** — 사용하지 않음.
- **AWS S3 등 상용 클라우드 스토리지** — 사용하지 않음. 자체 호스팅 MinIO를 쓴다.

## 8. 시크릿 관리

- 실제 값은 **`.env` 파일 하나에 모여 있고 저장소에 커밋하지 않는다**
  (`.gitignore`: `.env`, `**/.env`, `*.env.txt`, `secrets/`, `*firebase*.json`).
- 배포에서는 Jenkins Credential **`starttoo-env-file`**(Secret file)이 그 `.env`를 대신하며,
  파이프라인이 `docker compose --env-file "$ENV_FILE"`로 주입한다.
- 값을 바꾸려면 Jenkins Credential 파일을 교체하고 재빌드한다.
  `VITE_*` 값은 프론트엔드 **이미지 재빌드**가 필요하다.

### 실제 키를 얻는 곳

이 문서에는 키·시크릿 값을 적지 않는다. 실제 값은 아래 두 곳에만 있고 내용은 서로 같다.

| 위치 | 설명 |
|---|---|
| 배포 서버 `~/S15P11D201/.env` | 운영에서 실제로 사용 중인 값 |
| Jenkins Credential `starttoo-env-file` (Secret file) | CI/CD가 주입하는 값. 위 파일과 동일 |

각 제공자 콘솔에서 다시 확인할 수도 있다.

| 키 | 확인 위치 |
|---|---|
| `KAKAO_CLIENT_ID` | Kakao Developers → 내 애플리케이션 → 앱 키 → REST API 키 |
| `VITE_KAKAO_JS_KEY` | Kakao Developers → 내 애플리케이션 → 앱 키 → JavaScript 키 |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | Google Cloud Console → API 및 서비스 → 사용자 인증 정보 → OAuth 클라이언트 ID |
