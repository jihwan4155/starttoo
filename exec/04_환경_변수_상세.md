# starttoo 환경 변수 상세 가이드

빌드·배포 시 사용되는 모든 환경 변수의 용도, 형식, 소비 위치, 기본값을 변수 단위로 정리한 문서다.
작성 기준일: 2026-08-10 / 기준 커밋 `9b2f355`

> **이 문서에는 실제 시크릿 값을 적지 않는다.** 저장소에 남기지 않기 위해서다.
> 실제 값은 배포 서버 `~/S15P11D201/.env`와 Jenkins Credential `starttoo-env-file`(둘은 같은 내용)
> 에만 있다. 각 값의 **형식과 만드는 방법**은 이 문서로 충분히 재현할 수 있다.

---

## 1. 주입 구조 — 값이 컨테이너까지 가는 길

```
[.env 파일]  또는  [Jenkins Credential starttoo-env-file]
     │  docker compose --env-file <파일>
     ▼
[docker-compose.yml]
     ├── environment:  →  런타임 환경 변수 (컨테이너 재생성으로 반영)
     └── build.args:   →  빌드 시점 변수 (이미지 재빌드 필요, VITE_*)
     ▼
[각 애플리케이션 설정]
     ├── backend: application.yml 의 ${KEY:기본값} 플레이스홀더
     ├── ai-api:  FastAPI Settings (APP_*, API_PREFIX 등)
     └── ai:      os.environ 직접 참조 (COVERUP_*)
```

기본값이 **두 겹**이라는 점에 주의한다.

1. `docker-compose.yml`의 `${KEY:-기본값}` — `.env`에 키가 없을 때 compose가 채우는 값
2. `application.yml`의 `${KEY:기본값}` — 환경 변수 자체가 없을 때 Spring이 채우는 값

`.env`에 키를 지워도 서비스는 (1)의 로컬 기본값으로 뜬다. 즉 **`.env` 없이 `docker compose up`을
해도 로컬에서는 동작**하지만, 그 기본값들은 전부 로컬 개발용이므로 운영에서는 반드시 채워야 한다.

### 1.1 이름이 바뀌어 들어가는 변수 (compose가 매핑)

`.env`의 키 이름과 컨테이너가 받는 키 이름이 다른 경우가 있다. `.env` 쪽 이름으로 관리한다.

| `.env` 키 | 컨테이너가 받는 키 | 대상 |
|---|---|---|
| `POSTGRES_DB` | `DB_URL` (`jdbc:postgresql://postgres:5432/<DB>`) | backend |
| `POSTGRES_USER` | `DB_USERNAME` | backend |
| `POSTGRES_PASSWORD` | `DB_PASSWORD` | backend |
| `MINIO_ROOT_USER` | `MINIO_ACCESS_KEY` | backend, ai |
| `MINIO_ROOT_PASSWORD` | `MINIO_SECRET_KEY` | backend, ai |
| `AI_APP_NAME` / `AI_APP_ENV` / `AI_APP_RELOAD` / `AI_APP_LOG_LEVEL` | `APP_NAME` / `APP_ENV` / `APP_RELOAD` / `APP_LOG_LEVEL` | ai-api |
| `AI_API_PREFIX` | `API_PREFIX` | ai-api |
| `AI_CORS_ORIGINS` | `CORS_ORIGINS` | ai-api |
| `MINIO_PUBLIC_ENDPOINT` | `DESIGN_UPLOAD_ALLOWED_ORIGINS` | ai-api (도안 업로드 원본 검증) |

### 1.2 compose가 고정으로 박아 넣는 값 (`.env`로 못 바꾼다)

`REDIS_HOST=redis`, `REDIS_PORT=6379`, `MINIO_ENDPOINT=http://minio:9000`,
`SPRING_JPA_HIBERNATE_DDL_AUTO=validate`, `APP_HOST=0.0.0.0`, `APP_PORT=8000`,
`COVERUP_STORE=/data/coverup_store` — 컨테이너 간 네트워크 주소와 안전장치라 의도적으로 고정했다.

## 2. 빌드 시점 변수와 런타임 변수의 구분

| 구분 | 변수 | 반영 방법 |
|---|---|---|
| **빌드 시점** (이미지에 박힘) | `VITE_KAKAO_JS_KEY`, `VITE_GOOGLE_CLIENT_ID`, `VITE_API_BASE_URL` | 프론트엔드 **이미지 재빌드** 필요. `docker compose up -d`만으로는 반영되지 않는다 |
| **런타임** | 나머지 전부 | 컨테이너 재생성(`up -d`)으로 반영 |

Vite는 빌드 시점에 `import.meta.env.VITE_*`를 번들 문자열로 치환한다. 그래서
`docker-compose.yml`이 이 값들을 `build.args`로 넘기고, `frontend/Dockerfile`이 `ARG`로 받는다.
**`VITE_` 접두사 값은 전부 브라우저에 노출된다** — 비밀 값을 절대 `VITE_`로 만들지 않는다.

Jenkins 배포는 매번 Build 스테이지(`docker compose build`)를 거치므로 실무에서는 Credential
파일만 바꾸고 재빌드하면 두 종류 모두 반영된다.

## 3. 변수 사전

표기: **필수** = 운영 배포에서 반드시 채워야 하는 값. 기본값 = `.env`에 없을 때 적용되는 값.

| 키 | 필수 | 형식 / 만드는 법 | 소비처 | 설명 |
|---|---|---|---|---|

### 3.7 백엔드 타임아웃 · 배치 튜닝

기본값으로 두어도 동작한다. **compose 배선** 열이 ❌인 키는 `docker-compose.yml`의
`environment:`에 없어서 **`.env`에 넣어도 컨테이너에 전달되지 않는다** — 바꾸려면
compose에 배선을 추가해야 한다.

| 키 | 기본값 | compose 배선 | 설명 |
|---|---|---|---|
| `AI_GENERATION_TIMEOUT` | `60m` | ✅ | 도안 생성 대기 상한. GPU 릴레이 운영에서는 짧게 잡는다 |
| `AI_BATCH_TIMEOUT_PER_IMAGE` | `45s` | ❌ | 게시물 배치 분류 이미지당 타임아웃. CPU 추론 실측 장당 약 23초의 2배 |
| `AI_BATCH_TIMEOUT_OVERHEAD` | `10s` | ❌ | 배치 분류 고정 오버헤드 |
| `AI_CLASSIFICATION_BACKFILL_CRON` | `0 */5 * * * *` | ❌ | 비동기 워커가 놓친 분류를 주워 가는 백필 잡 주기 |
| `AI_CLASSIFICATION_MAX_ATTEMPTS` | `5` | ❌ | 분류 재시도 상한 |
| `AI_CLASSIFICATION_BACKFILL_BATCH_SIZE` | `20` | ❌ | 백필 1회 처리량 |
| `AI_CLASSIFICATION_RETRY_DELAY` | `5m` | ❌ | 분류 재시도 간격 |
| `MAX_IMAGE_BYTES` | `15728640` (15MB) | ✅ | 이미지 업로드 상한(백엔드). nginx `client_max_body_size 100m`와 별개 |

이 밖에 `application.yml`에는 `DB_POOL_MAX(20)`, `DB_POOL_MIN(5)`, `SERVER_PORT(8080)`,
`FLYWAY_OUT_OF_ORDER(true)`, `RATE_LIMIT_*`(엔드포인트군별 요청 한도),
`SEARCH_*`(검색 로그·자동완성 갱신 주기), `ARCHIVE_MAX_DESIGNS(20)`,
`AR_SESSION_TTL(10m)`·`AR_SESSION_MAX_DESIGNS(20)`·`AR_SESSION_MAX_COMPOSITES(30)`·
`AR_SESSION_DESIGN_URL_EXPIRY(1h)` 플레이스홀더가 더 있다. 전부 compose에 배선돼 있지
않아 운영에서는 기본값으로 돈다. 목록과 기본값의 원본은
[backend/src/main/resources/application.yml](../backend/src/main/resources/application.yml)이다.

| `SMS_WEBHOOK_URL` / `SMS_API_KEY` | **빈 값** | 문자 인증은 비용 문제로 실제 발송하지 않는다(화면 고정 코드 `1111`). 발송을 붙이게 되면 채운다 |

### 3.10 프론트엔드 로컬 개발 전용 (`frontend/.env.local`, 커밋 금지)

배포와 무관하게 개발자 PC에서만 쓰는 값이다. 원본 설명은
[frontend/.env.example](../frontend/.env.example)에 있다.

| 키 | 설명 |
|---|---|
| `VITE_API_PROXY_TARGET` | vite dev 프록시(`/v1`, `/ws`)가 향할 백엔드. 배포 백엔드를 볼 때 `https://starttoo.duckdns.org` — CORS 때문에 직접 호출은 403이라 반드시 프록시를 거친다 |
| `VITE_AI_PROXY_TARGET` | `/ai-service` 프록시 대상. 미설정 시 API 타깃으로 간다 |
| `VITE_EXTRACT_API_BASE_URL` | 도안 추출 요청 주소 오버라이드. 미설정 시 `/ai-service/api/v1` |
| `VITE_AR_JOIN_ORIGIN` | AR QR가 가리킬 오리진. 폰은 `localhost`로 못 들어오므로 PC의 LAN 주소를 넣는다 |
| `VITE_ENABLE_QA_MOCK_DATA` | API가 빈 배열일 때 화면에 샘플 데이터를 채우는 QA 장치. 기본 `false` |

## 4. 시크릿 취급 규칙

1. **실제 값은 git에 절대 올리지 않는다.** `.gitignore`가 `.env`, `**/.env`, `*.env.txt`,
   `secrets/`, `*firebase*.json`을 막고 있다. 이 문서를 포함한 exec 문서에도 값을 적지 않는다.
2. 실제 값이 존재하는 곳은 두 곳뿐이고 내용은 서로 같다.
   - 배포 서버 `~/S15P11D201/.env`
   - Jenkins Credential `starttoo-env-file` (Secret file)
3. 새 시크릿이 필요하면 위 명령(3.1 표의 "만드는 법")으로 생성하고, **두 곳을 함께** 갱신한다.
   한쪽만 바꾸면 수동 배포와 Jenkins 배포의 값이 갈라진다.
4. OAuth 키(구글·카카오)는 콘솔에서 재발급으로 로테이션한다. 확인 위치는
   [02 문서 8장](02_외부_서비스_정보.md).
5. 값이 노출됐다면: `JWT_SECRET`·내부 토큰은 즉시 교체(영향: 전 사용자 로그아웃),
   `POSTGRES_PASSWORD`는 `ALTER USER` + `.env` 동시 교체, OAuth secret은 콘솔 재발급.

## 5. 변경 반영 절차 (운영)

```
Jenkins Credential(starttoo-env-file) 파일 교체
  → dev 브랜치 재빌드 (또는 서버 ~/S15P11D201/.env 수정 후 수동 배포)
  → docker compose build + down/up  (수십 초 다운타임, 01 문서 9장 3번)
```

- 런타임 변수만 바꿨다면 서버에서 `docker compose --env-file .env up -d`로도 반영된다.
- `VITE_*`를 바꿨다면 프론트엔드 **이미지 재빌드**가 필수다(2장).
- `POSTGRES_PASSWORD`는 초기화된 볼륨에는 자동 적용되지 않는다(3.1 표 참고).
